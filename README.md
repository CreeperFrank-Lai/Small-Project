# Small-Project
第二組 資工2B賴宇帆 資工2B郭聿嘉 資工2A李浩廷  
專題題目:電子寵物  
這是一款文字介面的養成遊戲，玩家必須在寵物的各項指標與金幣之間取得平衡，最終目標是透過購買「皇冠」來達成遊戲勝利！

### 📊 1. 基礎屬性管理
寵物擁有三大關鍵指標，這些指標會隨著玩家的行動以及**「時間流逝」**而動態變化：
* **飢餓度**：數值越高代表越餓。
* **快樂度**：數值越高代表越開心。
* **清潔度**：數值越低代表越髒。

### 💰 2. 金幣與商店經濟系統
* **收入來源（賣藝 Perform）**：寵物可以透過賣藝來賺取金幣，但這會**大幅消耗體力與清潔度**。
* **日常支出**：餵食、玩耍、看醫生或購買道具均需消耗金幣。
* **商店功能 (Shop)**：商店販售高級飼料、玩具組、清潔噴霧等道具。
* **🏆 終極勝利條件**：努力賺錢並在商店中成功購買 **「皇冠 (Crown)」**，即可通關遊戲！

### 🩺 3. 健康管理與強制醫療系統
遊戲中設計了自動健康檢測機制，玩家不能一味地讓寵物工作賺錢：
* **生病觸發條件**：當 **飢餓度 $\ge$ 85** 或 **清潔度 $\le$ 20** 時，寵物會立刻進入「生病」狀態。
* **強制醫療流程**：一旦寵物生病，系統會觸發緊急醫療檢查流程，**強制玩家優先處理寵物的健康問題（看醫生）**，此時將無法進行其他一般活動。

## 🛠 程式架構與 UML 設計

本專案架構清晰，主要由三個類別（Class）交互運作：
1. **`PetGame`**：負責控制遊戲的主迴圈（Game Loop）、處理玩家輸入、驅動時間流逝，以及觸發強制醫療檢查。
2. **`Pet`**：核心資料模型，封裝了寵物的所有屬性（姓名、飢餓度、快樂度、清潔度、金幣、生病狀態等）與行為（餵食、賣藝、玩耍、看病）。
3. **`Shop`**：商店類別，負責顯示商品選單並處理與 `Pet` 物件之間的交易邏輯。

### 類別關係說明
* `PetGame` **has-a (擁有)** `Pet` 物件。
* `PetGame` **uses (使用)** `Shop` 的功能。
* `Shop` 在處理交易時會 **uses (使用)** 到 `Pet` 物件來扣除金幣與改變屬性。
